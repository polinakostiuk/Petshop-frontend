# PetShop: фронтенд

Простий фронтенд для магазину товарів для тварин (HTML + CSS + JavaScript, без збирання). Уся логіка в одному файлі [`index.html`](index.html), сторінки перемикаються через адресу з `#` (`#/login`, `#/profile`).

Бекенд: [Petshop](https://github.com/polinakostiuk/Petshop).

## Що вміє

| Сторінка | Адреса | Хто може відкрити |
|---|---|---|
| Каталог товарів | `#/` | усі |
| Реєстрація | `#/register` | лише неавторизовані |
| Вхід | `#/login` | лише неавторизовані |
| Мій профіль (дані з `GET /api/users/me`) | `#/profile` | лише авторизовані |

Поведінка:

- Неавторизований, який відкриває профіль, потрапляє на сторінку входу; після входу повертається на профіль.
- Авторизований не може відкрити вхід чи реєстрацію: його перенаправляє на каталог.
- Неавторизований бачить у меню «Увійти» і «Реєстрація», але не бачить «Вийти». Авторизований бачить своє ім'я та «Вийти», але не бачить «Увійти».
- Вихід видаляє збережені токени (access і refresh) у браузері.
- Токени зберігаються в `localStorage`. Access-токен діє 5 хвилин. Коли він закінчується, фронтенд сам отримує новий через refresh-токен (`POST /api/auth/refresh`) і повторює запит. Якщо refresh теж закінчився (7 днів), показується сторінка входу.
- Помилки валідації з бекенду (наприклад, «Паролі не збігаються.») показуються під відповідним полем.

## Як запустити проєкт

| Частина | Адреса |
|---|---|
| Бекенд (Django) | http://127.0.0.1:8000 |
| Фронтенд | http://127.0.0.1:3000 |

### 1. Запустити бекенд

```bash
git clone https://github.com/polinakostiuk/Petshop.git
cd Petshop
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver 8000
```

### 2. Запустити фронтенд

У окремому терміналі:

```bash
git clone https://github.com/polinakostiuk/Petshop-frontend.git
cd Petshop-frontend
python3 -m http.server 3000 --bind 127.0.0.1
```

Відкрийте в браузері http://127.0.0.1:3000. Зареєструйтеся на сторінці «Реєстрація», увійдіть і відкрийте «Профіль».

> [!IMPORTANT]
> Відкривайте сторінку саме за адресою `http://127.0.0.1:3000`, а не подвійним кліком по `index.html` (`file://...`). Бекенд дозволяє CORS-запити лише з `http://127.0.0.1:3000`, `http://localhost:3000` та `63342` (вбудований сервер PyCharm/WebStorm).

## Налаштування

Адреса бекенду задана константою `API_URL` на початку скрипта в [`index.html`](index.html):

```js
const API_URL = 'http://127.0.0.1:8000/api';
```

Якщо запустили Django на іншому порту, змініть її. Якщо запускаєте фронтенд на іншому порту, додайте його origin у `CORS_ALLOWED_ORIGINS` у `config/settings.py` бекенду.

## Якщо щось не працює

| Що видно | Причина |
|---|---|
| «Не вдалося зв'язатися з сервером...» | бекенд не запущено, або фронтенд відкрито з адреси, якої немає у `CORS_ALLOWED_ORIGINS` |
| «Невірне ім'я користувача або пароль.» | неправильний логін чи пароль |
| «Товарів поки немає.» | усе працює, але в базі ще немає товарів |
